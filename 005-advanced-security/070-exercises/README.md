## 답안 원칙

```text
Risk
→ Prevention / Detection point
→ Selected GitHub feature
→ Why
→ Alternative and why less appropriate
→ Remediation / Governance
→ Verification / Evidence
```

## 완료 기준

- [ ] 5개 영역 모두 수행
- [ ] 80% 이상 자료 없이 설명 가능
- [ ] 기능 이름뿐 아니라 Risk와 선택 이유 설명
- [ ] Alert 상태 변경·예외는 근거와 Governance 포함
- [ ] 실제 Production 보안 설정을 학습 목적으로 약화시키지 않음
- [ ] 실제 민감정보를 실습 자료에 사용하지 않음
