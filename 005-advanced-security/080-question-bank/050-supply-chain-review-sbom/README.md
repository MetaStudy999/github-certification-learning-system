# 문제은행 (Question Bank, QB) 050 — 의존성 리뷰 / SBOM (Dependency Review / SBOM, DRSBOM)

## Q041–Q050

**Q041.** PR에서 새로 추가된 의존성의 보안 영향을 확인할 때 가장 적절한 기능은? A. Dependency Review B. Secret Protection C. Actions Cache D. Pages  
**Q042.** SBOM과 Dependency Graph의 관계를 가장 잘 설명한 것은? A. 둘 다 구성요소 파악에 도움되지만 SBOM은 표준화된 명세로 활용 가능 B. 완전히 동일 C. 둘 다 코드 분석 엔진 D. 둘 다 인증 기능  
**Q043.** 취약한 Transitive Dependency가 발견되었다. 가장 먼저 확인할 것은? A. 어떤 상위 의존성을 통해 유입되었는지 B. README 제목 C. Repository Star 수 D. Issue Template  
**Q044.** 자동 의존성 업데이트를 무조건 Merge하면 안 되는 이유는? A. 호환성·테스트·위험 검토가 필요 B. GitHub가 허용하지 않음 C. SBOM이 삭제됨 D. Branch가 사라짐  
**Q045.** 대규모 조직에서 SBOM 활용의 장점은? A. 구성요소 인벤토리와 영향 분석 지원 B. 사용자 비밀번호 변경 C. PR Reviewer 자동 지정 D. Runner 생성  
**Q046.** Dependency Review를 Merge Gate와 연결할 때 핵심은? A. 정책 기준에 맞는 의존성 변경만 통과시키는 것 B. 모든 PR 차단 C. 모든 Alert 무시 D. Branch 삭제  
**Q047.** 취약점 Alert 우선순위 판단에 도움이 되는 요소는? A. 영향 범위와 실제 사용 여부 B. 파일 이름 길이 C. Commit 이모지 D. Repository 설명

**Q049.** SBOM을 규정 준수에 활용하려면 무엇이 중요한가? A. 최신성·정확성·추적 가능성 B. 글꼴 C. Repository 색상 D. 브랜치 수
