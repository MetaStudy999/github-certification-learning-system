# 문제은행 (Question Bank, QB) 070 — CodeQL / SARIF / 설정 (CodeQL / SARIF / Setup, CSARIFS)

## Q061–Q070

**Q061.** 빠른 도입과 낮은 관리 복잡성이 우선인 저장소에 적합한 방식은? A. Default Setup B. Advanced Setup C. 분석 비활성화 D. 수동 리뷰만  
**Q062.** 빌드 과정이나 분석 조건을 세밀하게 조정해야 할 때 적합한 방식은? A. Advanced Setup B. Default Setup만 C. Security Overview D. Push Protection  
**Q063.** SARIF의 장점으로 가장 적절한 것은? A. 여러 분석 도구 결과를 표준 형식으로 교환 B. Secret 암호화 C. 사용자 인증 D. Dependency 업데이트  
**Q064.** 다중 언어 저장소 분석 설계에서 먼저 확인할 것은? A. 지원 언어와 실제 빌드/코드 구조 B. Star 수 C. Issue 색상 D. Wiki 수  
**Q065.** 분석 결과가 너무 많을 때 가장 적절한 전략은? A. 위험·영향·신뢰도를 기준으로 우선순위화 B. 전부 무시 C. 전부 Dismiss D. 분석 중단  
**Q066.** CodeQL Alert의 설명과 경로 정보가 중요한 이유는? A. 문제의 원인과 데이터 흐름 이해에 도움 B. Repository 이름 변경에 필요 C. 비용 계산 전용 D. Branch 생성 전용  
**Q067.** Advanced Setup 변경 후 필요한 것은? A. 분석이 예상대로 실행되고 결과가 생성되는지 검증 B. 로그 제거 C. 모든 Alert 닫기 D. Security 기능 종료  
**Q068.** 외부 분석 도구 결과를 GitHub 보안 화면에 통합할 때 관련 개념은? A. SARIF B. SBOM만 C. SAML D. SCIM  
**Q069.** 정적 분석이 모든 보안 문제를 보장해서 찾는다고 볼 수 있는가? A. 아니다, 한계와 보완 통제가 있다 B. 항상 100% 찾는다 C. Secret만 찾는다 D. 의존성만 찾는다  
**Q070.** CodeQL 학습에서 가장 중요한 시험 관점은? A. Setup 선택·Alert 해석·운영 통합 B. Query 이름만 암기 C. 실제 취약점 악용 D. 모든 설정 우회
