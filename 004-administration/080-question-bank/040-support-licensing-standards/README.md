# 040 Support, Licensing, 표준 — Q031–Q040 (040 Support, Licensing, Standards — Q031–Q040, SLSQ031Q040)

## Q031
Enterprise Support에 문의하기 전 가장 적절한 준비는?

A. 재현 절차·영향 범위·시간·관련 로그 수집  B. Password 공유  C. 모든 권한 해제  D. Production 삭제

**정답: A** — 재현 가능한 진단정보가 Support 해결 속도를 높입니다.

## Q032
Support 자료에 포함하면 안 되는 것은?

A. 오류 시각  B. Workflow Run ID  C. Secret/Token 원문  D. 영향받은 Scope

**정답: C** — Credential 원문은 공유하지 않습니다.

## Q033
Enterprise 표준화를 위해 가장 효과적인 방법은?

A. 각 팀이 임의 설정  B. 공통 Policy·Template·Naming Standard 정의  C. Owner 무제한  D. Audit 제거

**정답: B** — 표준은 운영 복잡도와 정책 편차를 줄입니다.

## Q034
License 최적화를 위해 먼저 봐야 할 것은?

A. 활성 사용자와 실제 사용량  B. README 글자 수  C. PR 제목  D. Emoji 사용량

**정답: A** — 배정 대비 실제 활용도를 비교해야 합니다.

## Q035
비활성 사용자를 정리할 때 가장 중요한 것은?

A. 접근 회수와 업무 영향 검토  B. Commit 삭제  C. Repo Public 전환  D. Branch Rename

**정답: A** — Lifecycle과 Business Continuity를 함께 봅니다.

## Q036
관리 표준 문서에서 Scope를 명시해야 하는 이유는?

A. 정책 적용 대상과 예외를 명확히 하기 위해  B. Star 증가  C. Fork 제한  D. Issue 자동 종료

**정답: A** — Enterprise/Organization/Repository 경계를 명확히 합니다.

## Q037
지원 요청에서 "영향 범위"가 중요한 이유는?

A. 우선순위와 원인 범위를 좁히기 위해  B. License 삭제  C. README 생성  D. Branch 합치기

**정답: A** — 단일 사용자/조직/Enterprise 전체인지 구분해야 합니다.

## Q038
관리자가 반복 장애를 줄이려면 Support 종료 후 무엇을 해야 하는가?

A. Root Cause와 Prevention Action 기록  B. Log 삭제  C. 모든 권한 확대  D. 정책 비활성화

**정답: A** — Post-incident 학습을 운영 표준에 반영합니다.

## Q039
Enterprise 비용 예측에서 가장 적절한 방법은?

A. 사용자·Metered Product·성장률을 기준으로 추세 모델링  B. 임의 추정  C. 비용 확인 안 함  D. 월말에만 확인

**정답: A** — Usage 기반 Forecast가 필요합니다.

## Q040
운영 표준 변경의 최종 단계는?

A. 변경만 하고 종료  B. 적용 결과 검증과 문서 갱신  C. Audit 비활성화  D. Owner 추가

**정답: B** — 표준과 실제 상태가 일치해야 합니다.
