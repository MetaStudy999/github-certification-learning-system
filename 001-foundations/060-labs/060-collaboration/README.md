# Lab 060 — Collaboration

> **Labels · Assignees · Milestones · Discussions · Notifications**

## 000. Quick Start

이 Lab에서는 여러 사람이 같은 Repository에서 작업할 때 Issue와 Discussion을 정리하고 담당자와 목표를 관리하는 방법을 익힙니다.

## 010. Objective (목표)

완료 후 다음을 구분하고 사용할 수 있어야 합니다.

- Label(레이블)
- Assignee(담당자)
- Milestone(마일스톤)
- Discussion(디스커션)
- Notification(알림)

## 020. Concept (개념)

| 기능 | 사용 목적 |
|---|---|
| Label | Issue/PR을 유형·우선순위·상태 등으로 분류 |
| Assignee | 작업 책임자를 지정 |
| Milestone | 여러 Issue/PR을 하나의 목표나 일정으로 묶음 |
| Discussion | 질문·아이디어·공지처럼 즉시 작업 항목이 아닌 대화 |
| Notification | 참여·멘션·구독 대상의 변경 사항을 확인 |

## 030. Practice (따라하기)

### 031. Issue 생성

예시:

```text
Title: docs: improve quick start
```

### 032. Label 적용

사용 가능한 Label을 확인하고 적절한 것을 적용합니다.

예:

```text
documentation
help wanted
good first issue
```

Repository마다 Label 이름은 다를 수 있습니다.

### 033. Assignee 지정

권한이 허용되는 범위에서 자신 또는 Collaborator를 Assignee로 지정합니다.

관찰 포인트:

```text
누가 작업을 담당하는가?
```

### 034. Milestone 연결

가능한 경우 예시 Milestone을 만듭니다.

```text
Foundations Lab v1
```

그 후 관련 Issue를 연결하여 목표 단위로 묶습니다.

### 035. Discussion과 Issue 비교

Discussion이 활성화된 Repository라면 다음 유형의 글을 비교합니다.

```text
Discussion: 어떤 학습 순서가 좋을까요?
Issue: README의 Quick Start를 수정해야 합니다.
```

핵심:

```text
대화·질문·아이디어 → Discussion
구체적인 작업·버그·변경 → Issue
```

### 036. Notification 확인

GitHub 알림 화면에서 참여 중인 Issue/PR의 알림이 어떻게 나타나는지 확인합니다.

- Mention
- Review request
- Assign
- Subscribe / Unsubscribe

## 040. Challenge (스스로 해보기)

다음 상황에 가장 적합한 GitHub 기능을 선택합니다.

1. 버그 유형을 표시한다.
2. 누가 고칠지 지정한다.
3. 다음 릴리스까지 완료할 Issue를 묶는다.
4. 기능 아이디어에 대해 커뮤니티 의견을 받는다.
5. 내가 참여한 PR의 변경 소식을 확인한다.

## 050. Verify (검증)

- [ ] Label과 Assignee를 구분한다.
- [ ] Milestone의 목적을 설명한다.
- [ ] Discussion과 Issue를 구분한다.
- [ ] Notification이 발생하는 대표 상황을 설명한다.
- [ ] Issue를 분류·담당·목표 단위로 관리할 수 있다.
