# 010 Project Rubric — Foundations 통합 프로젝트 평가표

## 평가 목적

자격증 문제풀이와 실제 GitHub 사용 능력을 분리하지 않고 하나의 프로젝트에서 검증합니다.

## 평가 기준 (Rubric, RUB)

| 영역 | 확인 항목 | 배점 |
|---|---|---:|
| Repository | Repository 목적·Visibility·기본 구조 설명 | 10 |
| Documentation | README, LICENSE, CONTRIBUTING, SECURITY, CODEOWNERS | 15 |
| Issue Management | Issue, Label, Assignee, Milestone 사용 | 10 |
| Git Workflow | Clone/Pull, Branch, Commit, Push | 15 |
| Pull Request | PR 설명, Linked Issue, 변경 범위 확인 | 15 |
| Review & Merge | Review, Check, Merge 흐름 설명 | 10 |
| 프로젝트 (Projects, PRJ) | Item, Status, View를 활용한 추적 | 10 |
| Modern Development | Actions, Copilot, Codespaces 목적 구분 | 5 |
| Security | 2FA, Visibility, Branch 보호 개념 설명 | 5 |
| 증빙 (Evidence, EVD) | 화면/링크/Commit/PR 등 재현 가능한 기록 | 5 |
| **합계** | | **100** |

## 판정

- **90–100**: CLEAR 후보
- **80–89**: PASS
- **70–79**: 보완 후 재평가
- **69 이하**: 핵심 Lab 재수행

## 구두 설명 확인

프로젝트를 보지 않고 다음을 설명합니다.

1. Issue를 왜 먼저 만들었는가?
2. Branch가 `main`을 안정적으로 유지하는 데 어떤 역할을 했는가?
3. Pull Request와 Merge의 차이는 무엇인가?
4. CODEOWNERS와 SECURITY는 각각 어떤 문제를 해결하는가?
5. Actions, Copilot, Codespaces는 어떻게 다른가?
6. Fork가 필요한 상황과 필요하지 않은 상황은 무엇인가?

6문항 중 5문항 이상을 정확히 설명하면 설명 역량을 통과한 것으로 봅니다.
