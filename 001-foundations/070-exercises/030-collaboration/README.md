# 030 Exercise — Collaboration

## 목표

Issue, Pull Request(PR), Review, Discussion, Label, Assignee, Milestone을 실제 협업 흐름으로 연결합니다.

## 문제

1. Issue와 Discussion의 차이를 설명하세요.
2. Pull Request의 핵심 목적을 한 문장으로 적으세요.
3. Assignee와 Reviewer의 역할 차이를 설명하세요.
4. Label을 사용하는 이유를 예시 2개와 함께 적으세요.
5. Milestone이 여러 Issue를 묶는 데 유용한 이유를 설명하세요.
6. Draft Pull Request는 어떤 상황에 적합한가요?
7. Review에서 `Approve`, `Comment`, `Request changes`의 차이를 설명하세요.
8. Merge 전에 자동 Check와 Review를 요구하는 이유를 설명하세요.
9. Notification을 적절히 관리해야 하는 이유를 협업 생산성 관점에서 적으세요.
10. 다음 항목을 일반적인 GitHub Flow 순서로 정렬하세요.

```text
Merge
Issue
Review
Commit
Pull Request
Branch
Push
```

## Scenario

> README의 Quick Start가 잘못되어 수정이 필요합니다. `main`에 직접 Push하지 않고 동료 검토를 거쳐 반영하려고 합니다.

다음을 모두 포함해 절차를 작성하세요.

- Issue
- Branch
- Commit
- Push
- Pull Request
- Review
- Merge

## Challenge

실습 Repository에서 실제로 Issue 하나를 만들고, Branch에서 문서 한 줄을 수정한 후 PR을 생성해 Merge까지 수행합니다.
