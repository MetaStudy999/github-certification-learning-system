# 050 연습문제 (Exercise, EXR) — Security, 관리 와 커뮤니티 (Security, Administration & Community, SAC)

## 목표

계정 보안, Repository 보호, 조직 관리, Open Source와 InnerSource 개념을 구분합니다.

## 문제

1. 2FA(Two-Factor Authentication, 이중 인증)를 사용하는 목적을 설명하세요.
2. Repository Visibility의 Public / Private 차이를 설명하세요.
3. Branch Protection 또는 Ruleset이 필요한 이유를 적으세요.
4. `main` Branch에 직접 Push하지 못하게 하는 정책이 왜 필요한지 설명하세요.
5. Organization에서 Team을 사용하는 이유를 설명하세요.
6. 최소 권한 원칙(Least Privilege)을 GitHub Repository 권한에 적용한 예를 하나 적으세요.
7. Secret을 코드에 직접 Commit하면 안 되는 이유를 설명하세요.
8. Open Source와 InnerSource의 차이를 설명하세요.
9. 공개 프로젝트에 기여하기 전에 확인할 문서 3가지를 적으세요.
10. Star, Watch, Follow의 목적을 각각 간단히 설명하세요.

## Scenario A — 보안

> 팀의 `main` Branch는 배포 기준 Branch입니다. 누구나 직접 Push할 수 있고 Review 없이 Merge할 수 있습니다.

위험을 2가지 적고 개선 방안을 제안하세요.

## 시나리오 (Scenario, SCN) B — 커뮤니티 (Community, C)

> 회사 내부 여러 팀이 하나의 공통 Library에 기여하지만 소스는 외부에 공개하지 않습니다. 대신 Issue, PR, Review 등 오픈소스 방식으로 협업합니다.

이 모델을 무엇이라고 부르는지 설명하고 Open Source와 차이를 적으세요.
