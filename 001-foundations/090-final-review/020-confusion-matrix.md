# 020 Confusion Matrix — 헷갈리는 개념 비교

| 개념 A | 개념 B | 시험에서 구분할 핵심 |
|---|---|---|
| Git | GitHub | Git은 분산 버전 관리 시스템, GitHub는 Git 기반 협업 플랫폼 |
| Clone | Fork | Clone은 Local 복제, Fork는 GitHub 계정/조직 공간에 별도 Repository 생성 |
| Fetch | Pull | Fetch는 Remote 정보 가져오기, Pull은 가져온 뒤 현재 Branch에 통합 |
| Branch | Fork | Branch는 같은 Repository 내부 작업선, Fork는 별도 Repository |
| Issue | Discussion | Issue는 작업 추적, Discussion은 장기 토론·Q&A·아이디어 교류 |
| Pull Request | Merge | PR은 변경 제안·검토 과정, Merge는 변경을 대상 Branch에 실제 반영 |
| Assignee | Reviewer | Assignee는 작업 담당, Reviewer는 변경 검토 역할 |
| Label | Milestone | Label은 분류, Milestone은 목표 시점/릴리스 단위 묶음 |
| Star | Watch | Star는 관심/북마크 성격, Watch는 알림 구독 |
| Organization | Enterprise | Organization은 협업 단위, Enterprise는 여러 Organization을 상위에서 관리 |
| Team | Role | Team은 사용자 그룹, Role은 허용되는 권한 수준의 묶음 |
| Public | Private | 공개 접근 가능 여부 차이 |
| Branch Protection | Ruleset | 둘 다 보호 정책에 사용되지만 Ruleset은 더 폭넓고 중앙화된 규칙 관리에 사용 가능 |
| README | CONTRIBUTING | README는 프로젝트 소개, CONTRIBUTING은 기여 절차 |
| SECURITY | CODEOWNERS | SECURITY는 취약점 신고 정책, CODEOWNERS는 변경 검토 책임자 지정 |
| Actions | Codespaces | 자동화 실행 vs 개발환경 제공 |
| Actions | Copilot | Workflow 자동화 vs AI 개발 보조 |
| Projects | Issues | Projects는 여러 작업의 계획·보기, Issue는 개별 작업 추적 |
| Open Source | InnerSource | 외부 공개 협업 vs 조직 내부 오픈소스 방식 |
| Template Repository | Fork | 새 프로젝트 출발점 복제 vs 원본과 기여 관계가 있는 복제 |

## 사용법

1. 왼쪽 두 개념을 가리고 각각 정의합니다.
2. 차이를 한 문장으로 말합니다.
3. 실제 상황 예시를 하나씩 만듭니다.
4. 틀린 항목은 `120-wrong-answers`에 `COMPARE`로 기록합니다.
