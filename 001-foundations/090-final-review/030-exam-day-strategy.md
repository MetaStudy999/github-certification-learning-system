# 030 Exam Day Strategy — 시험 당일 전략

## 1. 문제를 읽는 순서

```text
요구사항/목적
→ 제약조건
→ BEST / MOST / FIRST 같은 핵심 표현
→ 선택지 비교
→ 가장 직접적인 GitHub 기능 선택
```

## 2. 1차 풀이

- 확실한 문제를 먼저 해결합니다.
- 한 문제에 지나치게 오래 머무르지 않습니다.
- 헷갈리는 문제는 핵심 단어보다 **상황의 목적**을 기준으로 판단합니다.

## 3. 2차 검토

특히 다음 유형을 다시 봅니다.

- Clone vs Fork
- Fetch vs Pull
- Issue vs Discussion
- Actions vs Codespaces vs Copilot
- Organization vs Enterprise
- Role vs Permission
- README / CONTRIBUTING / SECURITY / CODEOWNERS
- Open Source vs InnerSource

## 4. 오답을 줄이는 규칙

1. 기능 이름이 익숙하다는 이유만으로 선택하지 않는다.
2. `FIRST`가 있으면 최종 해결책보다 먼저 해야 할 행동을 찾는다.
3. `MOST appropriate`가 있으면 가능한 답이 아니라 가장 직접적인 답을 고른다.
4. 보안 문제는 최소 권한과 보호 강화 방향을 우선 검토한다.
5. Git 명령은 Local/Remote 동작 위치를 구분한다.

## 5. 시험 직전 30분

새로운 내용을 공부하지 않습니다.

```text
10분: Confusion Matrix
10분: 최근 오답
5분 : GitHub Flow + Repository 핵심 문서
5분 : Domain 이름과 약점 확인
```

## 6. 종료 전 확인

- 미응답 문제가 없는지 확인
- 조건 표현을 놓친 문제 재확인
- 선택지를 잘못 클릭하지 않았는지 확인

> 실제 시험 운영 규칙과 UI는 응시 시점의 공식 안내를 우선합니다.
