# 070 Repository Governance — Q061–Q070

> GH-900 학습목표 기반 자체 제작 문제입니다.

### Q061
Repository의 목적과 사용법을 가장 먼저 설명하는 파일은?
A. README.md  
B. SECURITY.md  
C. CODEOWNERS  
D. LICENSE

<details><summary>정답</summary>

**A** — README는 프로젝트 소개와 기본 사용법을 제공합니다.
</details>

### Q062
기여 절차와 PR 규칙을 안내하는 파일은?
A. CONTRIBUTING.md  
B. LICENSE  
C. CODEOWNERS  
D. .gitignore

<details><summary>정답</summary>

**A** — CONTRIBUTING은 기여자가 따라야 할 절차와 규칙을 설명합니다.
</details>

### Q063
취약점 신고 절차를 안내하는 파일은?
A. SECURITY.md  
B. README.md  
C. LICENSE  
D. FUNDING.yml

<details><summary>정답</summary>

**A** — SECURITY는 보안 취약점 신고 정책에 사용됩니다.
</details>

### Q064
특정 경로 변경 시 Review 책임자를 지정하려면?
A. CODEOWNERS  
B. LICENSE  
C. README  
D. CITATION

<details><summary>정답</summary>

**A** — CODEOWNERS는 경로별 소유자·검토 책임자를 지정합니다.
</details>

### Q065
코드의 사용·수정·배포 조건을 명확히 하려면?
A. LICENSE  
B. SECURITY.md  
C. CONTRIBUTING.md  
D. CODEOWNERS

<details><summary>정답</summary>

**A** — LICENSE는 법적 사용 조건을 명시합니다.
</details>

### Q066
중요 Branch에 직접 Push를 제한하려는 목적과 가장 관련 있는 것은?
A. Branch Protection/Ruleset  
B. Star  
C. Wiki  
D. Sponsors

<details><summary>정답</summary>

**A** — 보호 규칙은 중요 Branch의 변경 조건을 통제합니다.
</details>

### Q067
Repository를 외부에 공개하지 않으려면 가장 직접적으로 확인할 설정은?
A. Visibility  
B. Milestone  
C. Label  
D. Star

<details><summary>정답</summary>

**A** — Visibility는 Repository 공개 범위를 결정합니다.
</details>

### Q068
사용자의 읽기/쓰기 등 접근 수준을 설명하는 개념은?
A. Permission  
B. Topic  
C. Watch  
D. Release

<details><summary>정답</summary>

**A** — Permission은 Resource에 대한 허용 수준을 나타냅니다.
</details>

### Q069
Organization 구성원을 그룹화해 여러 Repository 접근을 관리하려면?
A. Team  
B. Branch  
C. Issue  
D. Gist

<details><summary>정답</summary>

**A** — Team은 Organization 사용자 그룹 관리에 사용됩니다.
</details>

### Q070
여러 Organization을 상위 수준에서 관리하려면 가장 관련 있는 단위는?
A. Enterprise  
B. Milestone  
C. Pull Request  
D. Project View

<details><summary>정답</summary>

**A** — Enterprise는 여러 Organization에 대한 상위 관리와 정책 적용에 사용됩니다.
</details>
