# 080 협업 Scenarios — Q071–Q080 (080 Collaboration Scenarios — Q071–Q080, CSQ071Q080)

> GH-900 학습목표 기반 자체 제작 문제입니다.

### Q071
재현 가능한 로그인 오류를 담당자와 함께 추적하려면?
A. Issue  
B. Discussion  
C. Star  
D. Gist

<details><summary>정답</summary>

**A** — Issue는 버그·기능·작업 추적에 적합합니다.
</details>

### Q072
다음 버전 방향에 대해 커뮤니티 의견을 장기적으로 수집하려면?
A. Discussion  
B. Commit  
C. Branch Protection  
D. Release only

<details><summary>정답</summary>

**A** — Discussion은 장기 토론과 Q&A에 적합합니다.
</details>

### Q073
Issue의 담당자를 지정하려면?
A. Assignee  
B. Reviewer  
C. Watcher  
D. Sponsor

<details><summary>정답</summary>

**A** — Assignee는 작업 담당자를 나타냅니다.
</details>

### Q074
PR 변경 내용을 검토할 사람을 요청하려면?
A. Reviewer  
B. Milestone  
C. Star  
D. Topic

<details><summary>정답</summary>

**A** — Reviewer는 Pull Request 변경 검토 역할입니다.
</details>

### Q075
여러 Issue를 `bug`, `docs`, `priority-high`처럼 분류하려면?
A. Label  
B. Fork  
C. Release  
D. Pages

<details><summary>정답</summary>

**A** — Label은 Issue/PR 분류에 사용됩니다.
</details>

### Q076
여러 Issue를 특정 출시 목표로 묶으려면?
A. Milestone  
B. Star  
C. Watch  
D. Codespace

<details><summary>정답</summary>

**A** — Milestone은 여러 작업을 목표 단위로 묶습니다.
</details>

### Q077
PR에서 자동 테스트 상태를 확인하는 것과 가장 관련 있는 것은?
A. Checks  
B. Star  
C. Topic  
D. Fork

<details><summary>정답</summary>

**A** — Checks는 자동 검증 결과와 연결됩니다.
</details>

### Q078
PR이 Issue #24를 해결하도록 연결하는 표현의 예로 적절한 것은?
A. `Closes #24`  
B. `Stars #24`  
C. `Forks #24`  
D. `Watches #24`

<details><summary>정답</summary>

**A** — Closing keyword를 사용해 PR과 Issue를 연결할 수 있습니다.
</details>

### Q079
`main`을 안정적으로 유지하면서 동료 검토를 받고 싶다. 가장 적절한 방식은?
A. Feature Branch → PR → Review → Merge  
B. `main` 직접 Push만 사용  
C. Repository를 매번 새로 생성  
D. Issue 대신 Star 사용

<details><summary>정답</summary>

**A** — Branch와 PR 기반 흐름은 변경을 분리하고 검토할 수 있게 합니다.
</details>

### Q080
GitHub Flow에서 Review 다음 단계로 가장 일반적인 것은?
A. 조건을 충족하면 Merge  
B. Repository 삭제  
C. Enterprise 생성  
D. Fork 제거만 수행

<details><summary>정답</summary>

**A** — Review와 Check를 통과한 변경은 대상 Branch에 Merge합니다.
</details>
