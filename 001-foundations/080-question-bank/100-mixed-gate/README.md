# 100 Mixed Gate — Q091–Q100

> GH-900 학습목표 기반 자체 제작 혼합 문제입니다.

### Q091
`git fetch`와 `git pull`의 차이로 가장 정확한 것은?
A. Fetch는 Remote 정보를 가져오고, Pull은 가져온 뒤 현재 Branch에 통합한다.  
B. Fetch는 Push를 수행한다.  
C. Pull은 Fork를 생성한다.  
D. 둘은 항상 동일하다.

<details><summary>정답</summary>

**A** — Fetch는 자동 통합하지 않지만 Pull은 통합까지 수행합니다.
</details>

### Q092
Clone과 Fork의 차이로 가장 정확한 것은?
A. Clone은 Local 복제, Fork는 GitHub 상의 별도 Repository 복제이다.  
B. 둘 다 동일한 Local 명령이다.  
C. Fork는 Enterprise에서만 가능하다.  
D. Clone은 PR 전용이다.

<details><summary>정답</summary>

**A** — Clone은 Local 작업 사본, Fork는 GitHub 상 별도 Repository를 만드는 개념입니다.
</details>

### Q093
Issue와 Discussion의 차이로 가장 적절한 것은?
A. Issue는 구체적 작업 추적, Discussion은 장기 토론·Q&A에 적합하다.  
B. 둘은 항상 동일하다.  
C. Discussion은 Git Commit을 대신한다.  
D. Issue는 정적 웹사이트를 배포한다.

<details><summary>정답</summary>

**A** — 두 기능은 협업 목적이 다릅니다.
</details>

### Q094
Actions, Copilot, Codespaces의 연결로 옳은 것은?
A. Actions=자동화, Copilot=AI 개발 보조, Codespaces=Cloud 개발환경  
B. Actions=AI, Copilot=보드, Codespaces=License  
C. 셋은 동일 기능  
D. 셋 모두 Issue 분류 기능

</details>

### Q095
README, CONTRIBUTING, SECURITY를 올바르게 연결한 것은?
A. 프로젝트 소개 / 기여 방법 / 취약점 신고 정책  
B. 취약점 신고 / License / AI 보조  
C. Review 책임 / Project Board / 2FA

</details>

### Q096
Organization과 Enterprise의 관계로 가장 적절한 것은?
A. Enterprise는 여러 Organization을 상위 수준에서 관리할 수 있다.  
B. Organization은 항상 Enterprise보다 상위다.  
C. 둘은 Branch 이름이다.  
D. 둘 다 Git 명령이다.

<details><summary>정답</summary>

**A** — Enterprise는 여러 Organization에 대한 상위 관리 계층입니다.
</details>

### Q097
`main`에 Merge하기 전에 승인과 자동 Check를 요구하려 한다. 가장 관련 있는 것은?
A. Branch Protection/Ruleset  
B. Star  
C. Sponsors  
D. Wiki

<details><summary>정답</summary>

**A** — 보호 규칙은 중요 Branch의 병합 조건을 통제합니다.
</details>

### Q098
외부 프로젝트에 기여하려고 Fork한 뒤 원본 저장소의 최신 변경을 추적하기 위한 Remote 이름으로 흔히 사용하는 것은?
A. upstream  
B. milestone  
C. runner  
D. label

<details><summary>정답</summary>

**A** — 원본 Repository Remote를 관례적으로 `upstream`이라 부르는 경우가 많습니다.
</details>

### Q099
회사 내부 여러 팀이 공통 코드에 오픈소스 방식으로 기여한다. 가장 적절한 개념은?

C. Sponsors
