# Mock Exam 02 — Answer Key

| Q | Answer | 핵심 이유 |
|---:|:---:|---|
| 01 | A | `git status`는 현재 Branch와 Working Tree 상태를 확인합니다. |
| 02 | A | `git switch -c`는 새 Branch를 만들고 전환합니다. |
| 03 | A | `git log --oneline`은 Commit 이력을 간단히 봅니다. |
| 04 | A | `git remote -v`는 Remote 이름과 URL을 확인합니다. |
| 05 | A | Fork 기반 기여에서 원본 Remote를 흔히 `upstream`이라 부릅니다. |
| 06 | A | PR은 변경 검토와 논의의 중심 객체입니다. |
| 07 | A | Closing keyword로 Issue를 연결·종료할 수 있습니다. |
| 08 | A | Assignee는 Issue/작업 담당자입니다. |
| 09 | A | Reviewer request는 PR 검토자를 지정합니다. |
| 10 | A | Projects는 작업 상태를 여러 View로 관리합니다. |
| 11 | A | Field는 상태·우선순위 등 사용자 정의 값을 관리합니다. |
| 12 | A | Filter는 조건에 맞는 Project 항목을 선별합니다. |
| 13 | A | Event/Trigger가 Workflow 실행을 시작합니다. |
| 14 | A | Runner는 Actions Job이 실행되는 계산 환경입니다. |
| 15 | A | Job은 Workflow 안의 주요 실행 단위입니다. |
| 16 | A | Copilot은 AI 기반 개발 보조 기능입니다. |
| 17 | A | Codespaces는 브라우저 기반 Cloud 개발환경을 제공합니다. |
| 18 | A | Team은 Organization 구성원을 그룹화합니다. |
| 19 | A | Permission은 Resource 접근 수준과 직접 관련됩니다. |
| 20 | A | Branch Protection/Ruleset은 중요 Branch 변경 정책을 강제합니다. |
| 21 | A | 2FA/Passkey는 인증 보안을 강화합니다. |
| 22 | A | Private Visibility는 외부 공개를 제한합니다. |
| 23 | A | LICENSE는 사용·수정·배포 조건을 명시합니다. |
| 24 | A | CONTRIBUTING은 기여 절차와 규칙을 안내합니다. |
| 25 | A | SECURITY는 보안 취약점 신고 정책을 안내합니다. |
| 26 | A | CODEOWNERS는 경로별 코드 소유자/검토 책임 지정에 사용됩니다. |
| 27 | A | Fork와 Template은 목적과 원본 관계가 다릅니다. |
| 28 | A | Watch는 알림 구독과 관련됩니다. |
| 29 | A | Star는 관심 표시·북마크 성격입니다. |
| 30 | A | Sponsors는 오픈소스 개발자/프로젝트 후원에 사용됩니다. |
| 31 | A | Marketplace는 GitHub 확장 기능을 찾는 곳입니다. |
| 32 | A | 조직 내부 오픈소스형 협업은 InnerSource입니다. |
| 33 | A | Fetch는 자동 통합하지 않으므로 별도 통합 단계가 필요합니다. |
| 34 | A | Pull은 Fetch + 통합의 의미를 가집니다. |
| 35 | A | Checks는 PR의 자동 검증 결과와 연결됩니다. |
| 36 | A | 보호 규칙으로 승인 Review 요구 조건을 설정할 수 있습니다. |
| 37 | A | 추적·담당자 지정이 필요한 작업은 Issue가 적절합니다. |
| 38 | A | 장기 의견 수렴과 Q&A는 Discussion이 적합합니다. |
| 39 | A | 기능별 Branch로 독립 개발할 수 있습니다. |
| 40 | A | 작은 Branch→PR→Review→Merge가 GitHub Flow의 핵심 패턴입니다. |

## Scoring

- 36–40: EXAM-READY 수준
- 34–35: READY — Final Mock 전에 오답만 보강
- 30–33: REVIEW — 약점 Domain과 관련 Lab 재수행
- 29 이하: NOT READY — 핵심 개념부터 재학습
